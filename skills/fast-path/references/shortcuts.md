# Shortcut catalogue

A shortcut is allowed only when its equivalence (eq) check proves the result matches the long path. If the check fails or cannot run, take the fallback and report it in one line: `fallback S<n>: <reason>`.

High-risk nodes (auth/security, data deletion, money movement or stored balances, schema migrations, prod deploys) take the full path with no shortcuts, except S3 and S9 (their eq check, the full suite at the gate, runs anyway). A dry-run probe still runs before the action, never instead of it. Reusing the project's vetted security or money code is not a shortcut: it is required, and such primitives are never hand-rolled.

| id | pattern | safe when | eq check | fallback |
|---|---|---|---|---|
| S1 | Reuse existing code, skill, script or cached result instead of rebuilding | Its contract (inputs, outputs, edge cases) appears to match the spec | Run the reused unit on EVERY case the request or spec lists, plus ≥1 edge case (empty, boundary, rounding, unicode). Each output must equal the expected value from the request or spec; if the spec is silent on a case, use an oracle (input file, stdlib, documented behaviour), never the reused unit itself. Any mismatch → ✗ | Implement to spec. Never patch the reused unit unless the task asks for it |
| S2 | Grep, then a targeted read (Read offset/limit; POSIX `sed -n a,bp`; PowerShell `Get-Content <f> \| Select-Object -Skip <a> -First <n>`); no re-read after a successful edit | The target is locatable by a unique symbol or string | The grep hit is unique and is the code being changed; the edit tool reported success | Read the whole file once |
| S3 | Run the affected tests first, the full suite once at the end | The test runner can select by file or name | Full suite passes at the final gate (or no new failures vs baseline) | Fix what fails, rerun the full suite. Never ✓ on affected tests alone |
| S4 | Codemod, sed or a template for the same edit at many sites | The edit is mechanical: same pattern, no per-site judgement. Write set is tracked files only (`git grep -l <old> -- <scope> ":!CHANGELOG*"`, minus applied migrations; files holding keep hits are edited by hand), never caches, build output, data or untracked files. Bytes outside the matches stay unchanged: on Windows `sed -i` can strip CR, so use `perl -pi -e` (Git Bash) or a Python byte replace (read `rb`, `.replace(b'old', b'new')`, write `wb`), never PowerShell `Get-Content`/`Set-Content` (re-encodes), and confirm `git ls-files --eol` reports the same line endings as before. No uncommitted changes in the target files that the codemod could clobber | Pre-count plain substring hits of the old name (no word-boundary flag). Classify each hit: symbol or derived name (`test_<old>`, comments, docs) → rename unless the request excludes it; unrelated identifier that merely contains the string, or history (CHANGELOG, release notes, applied migrations) → keep and list it. Changed = pre-count − kept; 0 unclassified hits remain; build and tests pass | Edit the remaining or odd sites by hand, then rerun the check |
| S5 | Early exit; no re-deriving established facts | Exit: the done-criteria verify already passed. Fact: it came from this session's tool output | Exit only after verify ✓. Cite the fact's source (command, file:line); nothing has written to that source since | Re-check with one cheap command |
| S6 | Cheap probe before an expensive action (`--dry-run`, `--help`, a small sample, a single test) | A probe exists that exercises the same code path, arguments and target. High-risk action (deploy, migration, data delete, money op) with no dry-run → a staging or test-env run is the probe; none → ask (a standing pre-authorization applies; the user's yes to the destructive confirm is that ask). Data delete: a read-only listing of the exact targets, including ignored and untracked files (`git ls-files -- <path>` for tracked files plus `git ls-files -o -- <path>` for untracked and ignored ones, so the confirm can say which are committed; no git or outside the repo → bash `rg --files --no-ignore --hidden <path>`, PowerShell `Get-ChildItem -Recurse -Force -File <path>`), is the probe and runs before the yes. High-risk code edits need no probe: full suite + a test asserting the security/money behaviour | The probe uses the same path, args and target as the full action. A probe that fails is not an eq failure: stop, diagnose, fix, re-probe; run the full action only after the probe passes | No equivalent probe exists → run the full action once with output captured, only if it is not destructive; if it is, ask. State-changing probes run on a copy in a fresh temp dir or a test env, never real data |
| S7 | Pass explicit paths, line numbers and decisions to the next step or subagent | The facts are fresh (no writes since) | The receiver confirms the path or symbol exists before using it | Receiver rediscovers with one grep |
| S8 | Reuse an earlier command's output instead of rerunning it | No writes to its inputs since that run | No edit, install or checkout touched those inputs since | Rerun the command |
| S9 | Run one failing test by name while iterating on a fix | The failure reproduces in isolation | The same test passes, then the full suite at the final gate | Run the test file, then the full suite |

## Not shortcuts (never allowed)

- Skipping, weakening, deleting or `xfail`-ing a test to get green.
- Marking a check ✓ without running it.
- Mocking the unit under test to make the verify command pass.
- Deriving a test's expected value from your own implementation instead of the request or spec.
- Using a remembered fact (from memory, docs or an earlier session) as if it were verified this session.
- Disabling lint, type checks or CI steps to save time.
