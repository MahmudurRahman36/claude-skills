# Security policy: harness-builder

## Reporting a vulnerability

Report it privately through GitHub's private vulnerability reporting: open https://github.com/MahmudurRahman36/claude-skills, go to the **Security** tab and click **Report a vulnerability**. If that button isn't there, open an issue that says only that you have a security report for harness-builder, with no details, and wait for a private channel.

Include the harness-builder version (the `<!-- generated by harness-builder ... -->` line in `HARNESS.md`), your Claude Code or Codex version, your OS, and the smallest tool call or input that shows the problem.

## What counts

The generated guard (`scripts/guard.py` and `guard.sh`) and the scripts promise that, during a Claude Code run:
- Bash runs only `ingest.py`, `check_run.py` or `render_report.py`, with a bare interpreter name and no shell operators;
- Read, Grep and Glob stay inside the harness folder;
- writes stay inside `runs/` (code also writes `memory/`);
- only the `<slug>-verifier` subagent can start, and every other tool is blocked;
- any error blocks the call, and `ingest.py` refuses to start unless the guard is running;
- an item is marked processed only if its scorecard passes the checks and appears in a report rendered by code.

Any way around one of these is a vulnerability. Add a failing case to `tests/test_hostile.py` if you can.

## Out of scope

- The guard is a tripwire, not a sandbox. It doesn't confine the operating system, other processes or the parent Claude Code session. For that, use `/sandbox` and permission deny rules.
- Codex harnesses have no guard; they rely on Codex's sandbox and approval settings.
- Harnesses generated by older versions keep their old scripts until you regenerate them.
